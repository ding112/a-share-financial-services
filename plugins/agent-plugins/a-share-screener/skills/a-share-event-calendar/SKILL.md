# A 股事件日历

description: 构建和维护 A 股短线研究事件日历，覆盖财报披露、业绩预告、
业绩快报、限售解禁、股东减持、停复牌、股东大会、监管函、问询函、政策会议、
产业大会和行业事件。适用于“列出下周有业绩预告、解禁或减持风险的股票”、
“未来两周 A 股事件日历”、“有哪些政策会议催化”等请求。

## Workflow

### Step 1: Define Coverage Universe

先确认要跟踪的范围：

- **股票池**：用户给定股票、题材股票池、行业股票池或全市场。
- **事件类型**：财报、业绩预告、解禁、减持、停复牌、监管、政策或行业会议。
- **时间范围**：未来一周、未来两周、本月、本季度或指定日期区间。
- **重要性口径**：高、中、低影响，或按短线波动风险排序。
- **数据来源**：交易所、巨潮资讯、公司公告、日历数据、新闻或用户提供资料。

### Step 2: Gather Events

按事件类型收集并验证：

**财务与披露事件**
- 年报、季报、半年报披露日期。
- 业绩预告、业绩快报、业绩说明会。
- 分红、配股、增发、可转债和再融资相关安排。

**交易与股本事件**
- 限售股解禁、解禁市值和解禁比例。
- 股东减持计划、减持进展和减持完成公告。
- 停牌、复牌、风险警示、退市风险提示。
- 股东大会、董事会、监事会和重大事项审议。

**监管与风险事件**
- 监管函、问询函、关注函、处罚决定和立案调查。
- 财务重述、审计意见异常、诉讼仲裁和重大担保。
- 舆情事件和政策监管变化。

**政策与行业事件**
- 重要政策会议、部委发布会、产业大会和行业展会。
- 行业数据发布、补贴规则、招标采购和监管截止日期。
- 海外政策、商品价格或汇率事件对 A 股行业的映射。

### Step 3: Calendar View

用可排序表格输出事件：

| 日期 | 事件 | 股票/行业 | 类型 | 影响 | 来源 | 需要观察 | 风险 |
|------|------|-----------|------|------|------|----------|------|
| | | | 财报/解禁/减持/监管/政策/行业 | 高/中/低 | | | |

影响等级要说明依据：

- **高**：可能改变题材强度、基本面预期、流动性或交易资格。
- **中**：可能影响短线情绪，但需要成交、公告或行业数据进一步确认。
- **低**：例行披露或影响范围有限，记录即可。

### Step 4: Weekly Preview

按周输出前瞻摘要：

**本周重点事件**
1. [日期]：[股票/行业] [事件] — 为什么重要、影响范围、需要观察什么。
2. [日期]：[股票/行业] [事件] — 可能利好、利空或不确定性。
3. [日期]：[政策/会议] — 相关题材和待验证信号。

**下周预告**
- 提前提示高影响事件、密集披露窗口或潜在风险。

**风险与失效条件**
- 哪些事件可能导致候选股票池被剔除或降级。
- 哪些信息需要等公告、交易所文件或数据源确认。

### Step 5: Output

- 默认输出 Markdown 事件表和周度摘要。
- 如果用户要求可导入表格，使用清晰列名，便于复制到电子表格。
- 必须写明数据来源；无法验证时标记“来源缺失”或“待验证”。
- 对解禁、减持、监管和停复牌事件优先提示风险。
- 不直接给出买入、卖出、加仓或减仓指令。

## Important Notes

- A 股事件日期经常变化，临近事件前必须重新核验交易所和公司公告。
- 解禁和减持不是自动利空，必须结合比例、流动性、股东类型和市场环境判断。
- 监管函、问询函和处罚需要区分事实、公司回复和市场解读。
- 政策会议和产业大会只能作为催化线索，不能替代公司层面的业务验证。
- 事件日历用于注意力分配和风险排查，不构成投资建议。
