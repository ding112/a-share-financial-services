# 01 — 贯通资产负债表明细

**What to build:** 从股票池到研究数据包贯通第一条财务报表明细 tracer bullet：沪深证券的资产负债表可以经 AkShare 或真实形状 fixture 转换为固定长表，同时生成来源清单和统一错误文件。该切片建立后续两张报表共用的数据契约、行项目规范化、稳定身份和黑盒验收接缝，但不接入一键准备流程。

**Blocked by:** None — can start immediately

**Status:** ready-for-agent

- [ ] 提供独立公开入口，接收股票池、输出目录、研究截止日、正整数报告期数量以及 `akshare|fixture` 来源；缺少股票池、缺少代码列、期间数量非法或没有有效证券时返回非零并留下稳定产物。
- [ ] 在线路径只通过现有 AkShare 单公司资产负债表接口获取数据，不增加直接东方财富适配器、不增加依赖、不静默回退。
- [ ] 成功运行生成 `financial_statements.csv`、来源清单条目和统一错误文件；现有 `financial_summary.csv` 契约和行为保持不变。
- [ ] 长表严格使用父规格定义的 22 个固定列及顺序，并正确填写证券、组织类型、报告期、报告类型、公告日、更新日、币种、审计意见和来源元数据。
- [ ] 资产负债表记录使用 `statement_type=balance_sheet`、`value_semantics=point_in_time`，来源未声明报表范围时 `statement_scope=来源缺失`。
- [ ] 只把独立披露的非空金额、数量或每股值展开成行；证券/报表元数据、审计元数据、`*_YOY` 和来源计算比例不生成行项目，空的非核心字段不生成记录。
- [ ] 已知金额项目单位为 `CNY`；其他已知数量项目依显式目录映射，不能根据字段名、`SHARE` 后缀、数值大小或币种字段猜测单位。
- [ ] 完整实现父规格中 21 个资产负债表核心科目的英文 snake_case 映射和固定顺序。
- [ ] 每个核心科目使用显式来源字段优先级；冲突时仅最高优先级行获得规范名称，其他非空来源行仍保留，不求和、不取最大值、不按企业类型猜测。
- [ ] 已有有效报表记录缺少核心科目时生成唯一占位行，使用 `core:<normalized_line_item>` 来源项目标识，值、单位和验证状态均为 `来源缺失`；整张表不存在时不生成占位行。
- [ ] 已识别且单位已知的来源行使用 `public_market_data` 和 `verified`，并明确该状态只表示成功定位与映射，不表示法定官方披露或合并口径。
- [ ] 行项目 ID 使用父规格定义的稳定身份键和 `fs_` 摘要格式，不包含数值、公告日、更新时间或接口返回顺序。
- [ ] 资产负债表行按证券代码升序、报告期降序、核心契约顺序、其他来源字段升序稳定排列；相同 fixture 重跑不产生顺序或 ID 漂移。
- [ ] 来源清单只有一个财务报表明细条目，并记录 AkShare/东方财富公开市场数据、研究截止日、期间数量、单位、时点语义、范围未知和缺失行为。
- [ ] 离线黑盒检查器通过子进程运行公开入口，只断言退出码和最终产物；成功 fixture 同时覆盖沪深样本、映射冲突、核心缺失、稳定 ID 与排序，不访问网络或导入私有实现。
