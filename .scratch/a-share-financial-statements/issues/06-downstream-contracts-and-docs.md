# 06 — 开放下游契约并完成交付说明

**What to build:** 让研究人员和下游 Agent 能发现并安全使用财务报表明细：数据来源契约公开固定字段和降级语义，可比分析可以读取规范核心科目但继续执行报表范围门槛，所有发布形态和使用说明保持同步，并通过全仓验收。

**Blocked by:** 05 — 接入一键准备与本地研究包

**Status:** ready-for-agent

- [ ] A 股数据来源契约把 `financial_statements.csv` 列为可选研究包文件，并完整说明固定字段、三表来源、可见版本、统一报告期窗口、期间语义、单位、验证状态和错误阶段。
- [ ] 数据来源契约明确区分“财务摘要”和“财务报表明细”，不得用最近一期摘要倒推多期三表。
- [ ] 数据来源契约明确 `verified` 只表示来源行已定位和映射，不代表 `official_disclosure`、合并口径或完整法定财报。
- [ ] 可比分析契约能够读取规范核心科目，但 `statement_scope=来源缺失` 时跨公司比较以及需要统一范围的派生计算必须写 `口径不可比` 或 `来源缺失`。
- [ ] 同公司、同来源趋势可以使用可见且期间语义一致的明细；不得因此绕过跨公司范围门槛。
- [ ] 不新增 EV、EV/Revenue、EV/EBITDA、自由现金流、单季度、TTM 或其他派生计算器，也不自动改变现有 comps 输出。
- [ ] 快速开始和 Managed Agent 使用说明记录默认执行、来源/期间参数、跳过方式、输出文件、沪深支持、北交所不支持、历史版本限制和失败降级。
- [ ] 路线图把财务报表明细阶段标为已接入，并保留完整财报、北交所三表和派生计算等后续边界。
- [ ] 所有 Skill 修改先落在垂直插件规范源，再通过现有同步流程传播到命名 Agent bundle；规范源与 bundle 字节一致。
- [ ] 现有 A 股数据契约检查补充新文件、关键字段、核心边界和 bundle 同步断言，但不建立第二套功能测试接缝。
- [ ] 新增专项黑盒检查、研究包准备相关检查、A 股数据契约检查、插件全仓检查、Python 编译检查和 diff 格式检查全部通过，既有测试不得禁用或削弱。
- [ ] 在环境允许访问公开源时，对一个沪市和一个深市样本执行人工只读 AkShare smoke，核对三表字段形状和非空输出；若环境不允许网络，明确记录未执行原因且不得用联网结果替代离线验收。
- [ ] 最终交付说明列出可立即回滚的跳过方式，并确认功能未迁移既有数据、未修改核心文件格式、未新增运行时依赖。
