# A 股研报索引与 PDF 补充数据源 PRD

Status: ready-for-agent

## Problem Statement

A 股研究人员已经可以通过现有公开数据准备流程获得股票池、行情、估值、财务摘要、公司详情、年报和风险事件，但还不能在同一个 `research-pack` 中稳定获得与股票池对应的第三方个股研报索引和有限数量的原始 PDF。外部 `a-stock-data` 项目整理了东方财富研报接口及 PDF 定位方式，但它是包含 Python 示例的 Skill，而不是可以直接依赖的稳定 SDK；其返回值、失败语义和来源说明也不符合本项目现有研究数据包契约。

研究人员需要在不替换现有 AkShare、腾讯和东方财富数据路径、不引入新的运行时依赖、不把第三方研报误标为已验证证据的前提下，把东方财富研报索引和 PDF 作为补充数据源纳入一键数据准备流程。接口无数据、部分失败或完全不可用时，核心数据包仍应完成，并明确保留缺失原因。

## Solution

在现有一键 `research-pack` 准备流程中增加一个可选但默认执行的研报准备阶段。该阶段以股票池为默认范围，检索东方财富个股研报；只有用户显式提供东方财富行业代码时才检索行业研报，不从主题名称自动推断行业分类。

阶段输出一个稳定、可审计的研报索引和一个限量 PDF 目录。默认索引最近 730 天内每个证券或行业最多 20 条研报，并下载其中最新 3 份 PDF；用户可以调整限制或跳过 PDF 下载。研报索引与 PDF 统一标记为 `third_party`、`待验证`，不得自动进入财务摘要、业务暴露证据或 shortlist 排名。

研报准备失败不阻断核心数据包。检索无数据、索引失败和 PDF 下载失败必须具有不同的可观察结果。独立抓取器在全部索引请求失败时返回非零；一键准备流程将该失败作为可选阶段告警并继续完成核心数据包。

## User Stories

1. 作为 A 股研究人员，我希望一键准备数据包时默认获得股票池对应的研报索引，以便发现可继续核查的第三方研究材料。
2. 作为 A 股研究人员，我希望研报能力补充而不替换现有公开数据源，以便继续依赖已经验证的行情、财务和风险数据流程。
3. 作为 A 股研究人员，我希望默认只检索股票池内公司的个股研报，以便研报范围与当前研究对象保持一致。
4. 作为 A 股研究人员，我希望能够显式提供东方财富行业代码，以便在确实知道分类映射时补充行业研报。
5. 作为 A 股研究人员，我希望系统不根据主题名称自动猜测行业代码，以免产业链主题被错误映射到单一行业分类。
6. 作为 A 股研究人员，我希望所有检索都以指定的 `as-of` 为截止日，以便结果可以复现和审计。
7. 作为 A 股研究人员，我希望默认只索引最近 730 天的研报，以便材料保持相关性且抓取量可控。
8. 作为 A 股研究人员，我希望每个证券或行业默认最多保留 20 条索引，以免高覆盖公司占用过多数据包空间。
9. 作为 A 股研究人员，我希望每个证券或行业默认只下载最新 3 份 PDF，以便控制带宽、磁盘占用和源站压力。
10. 作为 A 股研究人员，我希望可以调整回溯窗口和每个对象的索引、PDF 上限，以便适应不同研究深度。
11. 作为带宽受限环境的使用者，我希望可以跳过 PDF 下载而仍保留研报索引，以便先完成低成本的数据发现。
12. 作为研究数据包使用者，我希望索引记录研报 ID、范围类型、证券或行业标识、标题、机构、发布日期和原始链接，以便定位具体材料。
13. 作为研究数据包使用者，我希望索引保留评级和盈利预测的原始字段，以便后续核查而不丢失源数据。
14. 作为研究数据包使用者，我希望索引记录 PDF 链接和本地相对路径，以便判断材料是否已经成功落盘。
15. 作为研究数据包使用者，我希望研报索引和 PDF 都明确标记为第三方、待验证，以免把机构观点误认为法定披露。
16. 作为研究数据包使用者，我希望 PDF 下载成功只表示材料已定位，以免下载状态被错误解释为内容已经验证。
17. 作为研究数据包使用者，我希望评级和盈利预测不会自动写入现有财务摘要，以免混用历史披露与机构预测口径。
18. 作为研究数据包使用者，我希望研报不会单独证明业务暴露、订单、客户或经营质量，以便维持现有证据门槛。
19. 作为研究数据包使用者，我希望研报不会单独驱动 idea shortlist 排名，以免第三方观点替代可验证研究事实。
20. 作为研究数据包使用者，我希望检索成功但没有研报时看到明确的无数据记录，以便区分无覆盖与接口故障。
21. 作为研究数据包使用者，我希望单个证券的索引请求失败时仍保留其他证券的成功结果，以便部分故障不会清空整个阶段。
22. 作为研究数据包使用者，我希望单份 PDF 下载失败时仍保留对应索引行，以便稍后通过原始链接重试或人工获取。
23. 作为研究数据包使用者，我希望所有索引和 PDF 错误进入统一错误文件，以便集中审计失败对象、来源、阶段和原因。
24. 作为一键准备流程的使用者，我希望研报来源完全不可用时核心股票池、行情和财务数据仍能生成，以便可选材料不阻断基本研究。
25. 作为独立抓取器的使用者，我希望所有索引请求都失败时命令返回非零，以免完全不可用的来源被误报为成功。
26. 作为独立抓取器的使用者，我希望部分成功或真实无数据时命令仍能正常完成，以便批量任务保留可用结果。
27. 作为重复运行任务的使用者，我希望相同输入产生稳定排序和稳定文件名，以便比较两次数据包时不会产生无意义漂移。
28. 作为重复运行任务的使用者，我希望已经存在且有效的 PDF 不被重复下载，以便减少网络请求和源站压力。
29. 作为维护者，我希望接入使用项目现有 HTTP 与文件处理能力，以便不新增 `mootdx`、`stockstats` 或其他运行时依赖。
30. 作为维护者，我希望东方财富请求具有超时、节流和有限重试，以便批量股票池不会因高频并发触发风控。
31. 作为维护者，我希望无效响应、HTML 错误页和非 PDF 内容不会被保存成 PDF，以便索引路径只指向可识别的文档。
32. 作为维护者，我希望文件名经过清理且写入被限制在研报输出目录内，以免标题中的特殊字符破坏路径或越界写入。
33. 作为维护者，我希望测试使用固定响应和合成 PDF，不依赖真实网络，也不把真实券商研报提交到仓库。
34. 作为维护者，我希望外部项目只作为端点和请求模式参考，以便本项目保持自身接口、错误语义和来源契约。
35. 作为维护者，我希望引用或改编外部代码时保留 Apache-2.0 所需归属，以便满足许可证要求。
36. 作为后续功能开发者，我希望正文抽取、摘要和页码引用被明确留到单独阶段，以便本阶段不隐式引入 PDF 解析和版权风险。

## Implementation Decisions

- `a-stock-data` 被视为端点目录和参考实现，不作为运行时包、子模块或隐式执行的外部 Skill 依赖。
- 本能力是补充数据源，不改变现有行情、财务、年报、风险事件及其默认来源。
- 第一阶段只接入东方财富研报索引和对应 PDF 源，不接入 i问财、同花顺或其他隐式兜底来源。
- 默认输入范围来自现有股票池。个股研报默认启用；行业研报仅在用户显式提供一个或多个东方财富行业代码时启用。
- 不实现主题名称、概念板块与东方财富行业代码之间的自动映射。
- 产出契约由一个研报索引和一个研报 PDF 目录组成。两者都是 `research-pack` 的可选补充材料，但一键准备流程每次都应创建其稳定输出形状，即使结果为空或来源失败。
- 研报索引必须至少记录：稳定报告 ID、范围类型、证券代码或行业代码、证券或行业名称、标题、机构、发布日期、报告类型、评级、原始盈利预测字段、原始详情链接、PDF 链接、本地相对路径、来源类型、来源名称、验证状态和口径。
- 个股和行业研报共用同一索引，通过范围类型与对应标识字段区分，不为两类报告建立平行文件契约。
- 所有研报元数据和 PDF 的来源类型固定为 `third_party`，验证状态固定为 `待验证`。下载成功不得改变该等级。
- 默认回溯窗口为截至 `as-of` 的 730 天。每个证券或行业最多保留 20 条索引，并按发布日期降序、稳定报告 ID 次序确定结果。
- 默认只下载每个证券或行业最新 3 份 PDF。索引上限、PDF 上限和回溯窗口允许通过公开参数调整。
- 一键准备流程默认检索索引并下载限量 PDF，同时提供只保留索引、跳过 PDF 下载的明确选项。
- 有效的既有 PDF 在重复运行时复用。强制刷新可以重建索引，但不应无条件重复下载内容相同且验证有效的文件。
- PDF 文件名必须由稳定报告 ID和经过清理、截断的可读元数据组成。所有本地路径必须是数据包内的相对路径。
- 下载器必须使用超时、串行节流、有限重试和明确的用户代理；不得绕过登录、验证码、访问控制或源站限流。
- PDF 落盘前必须验证成功状态、合理的响应大小和 PDF 文件签名；失败响应不得作为有效 PDF 保留。
- 真实 PDF 只写入被版本控制忽略的运行输出目录。测试使用合成 PDF，fixture 中不得包含真实第三方研报内容。
- 索引请求成功但无记录时，在统一错误/缺失记录中使用独立的 `research_report_index_no_data` 阶段，区别于请求或解析失败。
- 索引请求或解析失败使用 `research_report_index` 阶段；单份 PDF 失败使用 `research_report_pdf` 阶段。
- PDF 失败时保留索引行，并将本地相对路径标记为 `来源缺失`。不得删除整条研报元数据来隐藏下载缺口。
- 部分证券失败时保留所有成功对象并返回成功。所有索引对象均请求失败时，独立抓取器先写出索引、来源清单和错误文件，再返回非零。
- 一键准备流程把研报抓取器作为可选阶段：即使独立抓取器返回非零，也只记录告警并继续生成核心数据包。
- 来源清单必须分别声明研报索引和 PDF 目录，保留来源名称、访问时间、回溯窗口、排序与限量口径、验证状态和缺失行为。
- 研报评级、预测和观点不得自动合并到现有财务摘要、业务暴露证据、估值排序或 idea shortlist。
- 第一阶段不执行 PDF 正文抽取、OCR、表格解析、摘要、观点合并、页码引用或内容级证据升级。
- 实现不得新增运行时依赖；优先复用项目现有 HTTP、CSV、JSON、路径和错误记录模式。
- 领域 Skill 的修改必须发生在垂直插件的规范源中，再通过现有同步流程传播到命名 Agent bundle。
- 若直接改编外部项目中具有独创性的代码，必须保留 Apache-2.0 要求的许可证和归属说明；仅根据公开接口重新实现时仍应在开发说明中记录参考来源。

## Testing Decisions

- 只使用“一键准备 `research-pack`”这一最高层公开入口作为主要测试缝隙。测试观察命令退出结果和数据包外部产物，不断言内部 HTTP helper、循环次数或私有函数调用。
- 使用固定的研报索引响应与合成 PDF，禁止测试访问真实东方财富网络接口，确保测试稳定、快速且不触发源站风控。
- 成功场景必须验证：索引排序稳定、默认回溯与条数限制生效、PDF 下载数量受限、本地路径有效、来源清单包含完整口径、核心数据包仍可被现有下游读取。
- 部分失败场景必须验证：成功证券和成功 PDF 被保留，索引失败与 PDF 失败进入不同阶段，失败 PDF 的索引行仍存在且本地路径为 `来源缺失`，整个一键流程成功完成。
- 全部失败场景必须验证：独立研报抓取器返回非零并写出空索引、来源清单和错误记录；一键数据准备流程只告警并继续生成完整核心数据包。
- 无数据场景必须验证：成功空结果被标记为 `research_report_index_no_data`，不会与网络异常或解析异常混为一谈。
- 重复运行场景必须验证：索引顺序和文件名不漂移，已存在且有效的 PDF 被复用，不产生重复索引行。
- 跳过 PDF 场景必须验证：索引仍正常生成，PDF 目录保持稳定形状，来源清单明确记录未下载口径。
- 行业研报场景必须验证：没有显式行业代码时不触发行业请求；提供代码时结果进入同一索引并通过范围类型区分。
- PDF 安全场景必须验证：非 PDF 响应、过小响应、危险文件名和越界路径均被拒绝并记录错误。
- 测试先例沿用现有公开数据抓取器、年报抓取器、辅助抓取器和一键准备流程的 fixture 检查模式，不引入新的测试框架。
- 完成实现后必须运行研报专项检查、现有 A 股数据契约检查、一键准备检查以及仓库总检查；不得跳过或禁用既有测试。

## Out of Scope

- 替换现有 AkShare、腾讯或东方财富行情与财务数据路径。
- 接入 `a-stock-data` 的完整 Skill、全部端点或其运行时依赖。
- i问财鉴权、同花顺一致预期以及多来源研报合并或自动兜底。
- 根据主题名称、概念名称或自然语言自动推断东方财富行业代码。
- 研报 PDF 正文抽取、OCR、表格解析、摘要、观点聚合、页码引用和内容级证据验证。
- 将研报评级、目标价、盈利预测或观点自动写入财务摘要、估值模型、业务暴露结论或 shortlist 排名。
- 大宗交易、股东户数变化、龙虎榜或其他市场行为信号接入。
- 互动易问答接入。
- 新浪财务三表或其他详细报表接入。
- mootdx 行情、技术指标、新闻、热榜、涨停池、ETF 或 ETF 期权能力。
- 将真实第三方研报 PDF 纳入仓库 fixture、发布包或版本控制。

## Further Notes

- 已确认的后续接入路线图为：第二阶段“大宗交易与股东户数变化”，第三阶段“互动易”，第四阶段“财务三表”。
- “研报 PDF 正文抽取与自动引用”作为独立后续阶段记录，排在上述数据源接入阶段之后；启动前需要单独确定版权控制、文本抽取、表格解析、引用页码和证据升级规则。
- 大宗交易、股东户数变化及类似数据应沿用“市场行为信号”定义，只作为风险提示、交易语境和后续核查线索，不得作为基本面证据或买卖信号。
- 本 PRD 不要求创建 ADR。目前的补充数据源、单一来源和范围限制均可通过后续独立阶段扩展，尚未形成难以逆转的架构锁定。
