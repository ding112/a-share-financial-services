# A 股大宗交易与股东户数市场行为事实接入规格

Status: ready-for-agent

## Problem Statement

A 股研究人员已经可以通过一键准备流程获得股票池、行情、财务摘要、风险事件、年报与研报材料，但研究数据包仍缺少与股票池对应的大宗交易记录和股东户数历史快照。研究人员目前只能离开数据包另行查找这些公开事实，无法按统一的研究截止日复现，也无法区分真实无数据、来源失败、解析失败和字段冲突。

外部 `a-stock-data` 项目提供了东方财富相关接口的参考实现，但不能直接满足本项目的数据契约：其大宗交易实现没有完整分页；其股东户数实现使用面向全市场最新状态的 `RPT_HOLDERNUMLATEST`，不能可靠表达个股历史序列，并存在把户均持股字段映射到错误源字段的风险。现有 AkShare 大宗交易接口也只读取首个 5000 行页面，不能安全支撑较长回溯窗口。

研究人员需要把这两类公开信息作为“市场行为事实”加入同一个可选阶段。该阶段必须提供稳定、可审计、不会泄漏未来信息的结构化文件，同时保持领域边界：大宗交易折溢价、营业部名称和股东户数变化只能作为后续“市场行为信号”的输入，不能自动证明机构吸筹、筹码集中、利益输送、资金意图或未来价格方向。

## Solution

在现有一键研究数据包准备流程中增加一个默认执行、可以整体跳过的 `market_activity` 阶段。阶段只处理 `peer_universe.csv` 中的沪、深、北 A 股，使用东方财富公开数据中心的 `RPT_DATA_BLOCKTRADE` 获取逐笔大宗交易事实，使用 `RPT_HOLDERNUM_DET` 获取个股股东户数历史快照。

阶段输出两个相互独立的事实表：`block_trades.csv` 与 `shareholder_counts.csv`。默认情况下，大宗交易按研究截止日回溯 365 天，每个证券最多保留最新 50 笔；股东户数按统计截止日回溯 730 天，每个证券最多保留最新 8 个在研究截止日前已经公开可见的快照。用户可以分别调整两组窗口和上限。

抓取器完整处理分页，先执行研究截止日、回溯窗口、核心字段和一致性校验，再稳定排序并按上限截断。所有机器字段统一使用人民币元、股、户和百分比等基础计量单位。来源缺失或字段冲突保持为 `来源缺失`，不得伪装成零。来源未提供派生值时可以生成机械派生值，但必须标明计算口径；来源值与基础事实冲突时，保留基础事实、隔离派生值并记录解析错误。

该阶段是补充数据源，不改变核心研究包的完成条件。单个证券、单个数据集或整个阶段失败时保留其他成功结果；一键准备流程只输出告警并继续。独立抓取器只有在致命输入错误，或两个数据集对全部有效证券的请求/解析都失败时返回非零，而且必须先写出稳定空文件、来源清单和错误记录。

## User Stories

1. 作为 A 股研究人员，我希望一键准备研究数据包时默认获得股票池内公司的大宗交易记录，以便在同一数据包中核查公开交易事实。
2. 作为 A 股研究人员，我希望一键准备研究数据包时默认获得股票池内公司的股东户数历史快照，以便观察可比的披露变化。
3. 作为 A 股研究人员，我希望大宗交易和股东户数位于同一个市场行为事实阶段，以便一次控制该类补充数据是否运行。
4. 作为研究数据包使用者，我希望两类事实分别保存在两个表中，以免不同粒度和不同含义的数据被错误合并。
5. 作为 A 股研究人员，我希望抓取范围严格跟随 `peer_universe.csv`，以便结果与当前研究对象一致。
6. 作为 A 股研究人员，我希望股票代码统一为带交易所后缀的沪、深、北 A 股代码，以便与研究包内其他文件稳定关联。
7. 作为 A 股研究人员，我希望系统不自动执行全市场扫描，以免产生与研究范围无关的大规模请求和数据。
8. 作为 A 股研究人员，我希望所有事实遵守指定的研究截止日，以便历史研究包不会纳入当时尚不可见的信息。
9. 作为 A 股研究人员，我希望大宗交易只纳入交易日不晚于研究截止日的记录，以免泄漏未来交易。
10. 作为 A 股研究人员，我希望股东户数的统计截止日和公告日都不晚于研究截止日，以免把后来披露的历史快照回填到过去。
11. 作为 A 股研究人员，我希望默认回看 365 天的大宗交易，以便在请求量可控的前提下获得足够的交易背景。
12. 作为 A 股研究人员，我希望每个证券默认最多保留最新 50 笔大宗交易，以免活跃证券使数据包无限增长。
13. 作为 A 股研究人员，我希望默认回看 730 天的股东户数快照，以便覆盖多个报告周期。
14. 作为 A 股研究人员，我希望每个证券默认最多保留最新 8 个股东户数快照，以便兼顾变化观察和数据包大小。
15. 作为 A 股研究人员，我希望两类数据的回溯窗口和单证券上限可以分别调整，以便适配不同研究深度。
16. 作为研究数据包使用者，我希望大宗交易表保留交易日、收盘价、成交价、成交量、成交额和折溢价，以便审计单笔交易事实。
17. 作为研究数据包使用者，我希望大宗交易表保留公开的买方和卖方营业部名称，以便后续人工核查交易参与方。
18. 作为研究数据包使用者，我希望大宗交易表不包含交易后 1、5、10 或 20 日表现，以免在历史研究中引入未来信息。
19. 作为研究数据包使用者，我希望大宗交易表不包含买卖方向评分、机构属性推断或收益标签，以免抓取层替代研究判断。
20. 作为研究数据包使用者，我希望股东户数表同时保留统计截止日和公告日，以便判断快照何时对市场可见。
21. 作为研究数据包使用者，我希望股东户数表保留本次户数、上次户数、户数变化及变化率，以便审计变化如何得出。
22. 作为研究数据包使用者，我希望股东户数表保留户均持股数量、户均持股市值、总市值和总股本等可选事实，以便进行后续核查。
23. 作为研究数据包使用者，我希望股东户数表不包含区间股价涨跌幅，以免把同期行情误读为户数变化的结果。
24. 作为研究数据包使用者，我希望户数减少不会被自动标成筹码集中或主力吸筹，以便保持事实层和解释层分离。
25. 作为研究数据包使用者，我希望大宗交易折溢价和营业部信息不会被自动标成机构吸筹、利益输送或后续价格方向，以便避免无证据结论。
26. 作为机器处理者，我希望价格和金额统一使用人民币元、数量统一使用股、比率统一使用百分比，以便字段不依赖页面展示单位。
27. 作为机器处理者，我希望字段名显式包含单位，以便使用者不需要依赖外部文档猜测量纲。
28. 作为研究数据包使用者，我希望可选字段缺失时写 `来源缺失` 而不是零，以便未知值不会被误解为事实为零。
29. 作为研究数据包使用者，我希望核心字段缺失的坏行被拒绝并留下错误，而不是生成不可关联或不可计算的记录。
30. 作为研究数据包使用者，我希望一个坏行不会导致同一证券或其他证券的有效行被丢弃，以便最大限度保留可用事实。
31. 作为研究数据包使用者，我希望来源提供的折溢价和户数变化值优先保留，以便忠实反映公开源。
32. 作为研究数据包使用者，我希望来源未提供派生值时可以根据同一记录的基础事实机械补算，以便减少不必要的缺失。
33. 作为研究数据包使用者，我希望每个派生字段标明来自来源还是机械计算，以便审计其生成路径。
34. 作为研究数据包使用者，我希望来源派生值与基础事实超过允许舍入误差时标为 `来源缺失` 并记录错误，以免输出自相矛盾的数据。
35. 作为重复运行任务的使用者，我希望每条记录具有稳定的本地标识，以便比较两个研究数据包时识别同一事实。
36. 作为重复运行任务的使用者，我希望本地标识不会被表述为交易所或数据源官方编号，以免产生错误权威性。
37. 作为重复运行任务的使用者，我希望同一天、同价格、同数量且买卖方相同的多笔真实大宗交易仍被分别保留，以免去重吞掉交易事实。
38. 作为重复运行任务的使用者，我希望完全重复的大宗交易具有确定性的重复序号和稳定标识，以便结果顺序不会随接口返回顺序漂移。
39. 作为重复运行任务的使用者，我希望两个 CSV 具有稳定列顺序和稳定行排序，以便版本比较不产生无意义差异。
40. 作为研究数据包使用者，我希望请求成功但没有记录时看到独立的无数据通知，以便区分真实空结果和接口故障。
41. 作为研究数据包使用者，我希望大宗交易和股东户数分别记录无数据状态，以便一种数据为空时不掩盖另一种数据的状态。
42. 作为研究数据包使用者，我希望请求失败、响应结构异常和行解析失败进入对应数据集的失败阶段，以便定位问题来源。
43. 作为研究数据包使用者，我希望非空响应中所有行都因核心字段错误被拒绝时视为解析失败，而不是误报为无数据。
44. 作为批量任务使用者，我希望单个证券请求失败时仍保留其他证券和另一个数据集的成功结果，以便局部故障不清空整个阶段。
45. 作为独立抓取器使用者，我希望一个数据集全部失败而另一个数据集至少有正常响应时命令仍成功，以便保留可用的半阶段结果。
46. 作为独立抓取器使用者，我希望两个数据集对全部有效证券都请求或解析失败时命令返回非零，以免完全不可用被误报为成功。

## Implementation Decisions

- 新能力命名为 `market_activity`，中文领域名称为“市场行为事实”。抓取层只保存事实，不使用“交易信号”“资金意图”或“筹码集中事实”等解释性命名。
- 新增一个独立公开 CLI `fetch_a_share_market_activity.py`。它接收 `--peer-universe`、`--output-dir`、`--as-of`、两组回溯天数和单证券上限、`--source eastmoney|fixture` 与 `--fixture-scenario`。
- CLI 参数使用以下名称和默认值：`--block-trade-lookback-days 365`、`--block-trade-limit-per-security 50`、`--shareholder-lookback-days 730`、`--shareholder-limit-per-security 8`。
- Fixture 场景至少包括：`success`、`no-data`、`partial-failure`、`all-failure`、`invalid-row`、`derived-conflict`、`as-of-pagination`、`duplicate-block-trades`。输入文件错误通过合成股票池覆盖，不需要独立 fixture 场景。
- 输入范围只来自股票池的 `code` 列。支持沪、深、北 A 股并规范化为 `XXXXXX.SH`、`XXXXXX.SZ` 或 `XXXXXX.BJ`；不提供全市场模式和额外代码列表参数。
- 股票池文件缺失、缺少 `code` 列或没有任何有效 A 股代码是致命输入错误。抓取器仍写出稳定空 CSV、来源条目和错误记录，然后返回非零。
- 部分非法或不支持的代码使用 `market_activity_input` 阶段写入统一错误文件，保留原始代码并继续处理其他证券。
- 在线实现直接调用东方财富公开数据中心，不通过 AkShare 运行时包装，不自动回退到其他来源，也不新增依赖。
- 大宗交易使用 `RPT_DATA_BLOCKTRADE`，按证券代码和交易日期范围过滤。请求字段只包含交易当时成立的事实，不请求或不输出交易后 1、5、10、20 日涨跌幅。
- 股东户数历史使用 `RPT_HOLDERNUM_DET`，按证券代码请求。不得使用只表达全市场最新状态的 `RPT_HOLDERNUMLATEST`，户均持股数量映射到 `AVG_HOLD_NUM`。
- 两类请求均使用 `pageSize=500` 并从第一页开始顺序遍历。响应必须校验成功标志、结果对象、总页数和数据列表类型。
- 大宗交易的有效窗口为 `as-of - block_trade_lookback_days` 至 `as-of`，两端包含，判断字段为交易日。
- 股东户数的有效窗口按统计截止日判断，为 `as-of - shareholder_lookback_days` 至 `as-of`，两端包含；公告日还必须存在且不晚于 `as-of`。公告日在 `as-of` 之后的快照不能进入历史数据包。
- 分页停止条件基于过滤后的有效记录，而不是原始返回条数：来源耗尽、排序字段已经越过回溯起点，或已经获得足够多条通过研究截止日、窗口和核心字段校验的记录时才允许停止。
- 请求策略与现有研报抓取器保持一致：串行请求、30 秒超时、最多 3 次尝试、对 429 和可重试 5xx 状态重试、递增退避，并保证相邻请求至少间隔 1.1 秒。不得绕过登录、验证码、访问控制或限流。
- 阶段固定生成 `block_trades.csv` 和 `shareholder_counts.csv`。即使无数据、全失败或致命输入错误，也必须生成带完整表头的空文件。
- `block_trades.csv` 固定列顺序为：`block_trade_id`、`security_code`、`security_name`、`trade_date`、`close_price_cny`、`deal_price_cny`、`deal_volume_shares`、`deal_amount_cny`、`premium_discount_pct`、`premium_discount_pct_basis`、`buyer_name`、`seller_name`、`source_type`、`source_name`、`verification_status`、`basis`。
- `shareholder_counts.csv` 固定列顺序为：`shareholder_snapshot_id`、`security_code`、`security_name`、`statistical_end_date`、`announcement_date`、`holder_count`、`previous_holder_count`、`holder_count_change`、`holder_count_change_basis`、`holder_count_change_pct`、`holder_count_change_pct_basis`、`average_holding_shares`、`average_holding_market_value_cny`、`total_market_cap_cny`、`total_shares`、`source_type`、`source_name`、`verification_status`、`basis`。
- 两张表的 `source_type` 固定为 `public_market_data`，`verification_status` 固定为 `待验证`。来源名称分别明确为东方财富大宗交易和东方财富股东户数，不使用笼统的官方披露等级。
- 机器输出使用基础计量单位：价格和金额为人民币元，成交量、户均持股和总股本为股，股东户数为户，折溢价率和户数变化率为百分比数值。
- 东方财富 API 的 `DEAL_VOLUME`、`DEAL_AMT`、`AVG_HOLD_NUM`、`AVG_MARKET_CAP`、`TOTAL_MARKET_CAP` 与 `TOTAL_A_SHARES` 按返回的基础单位写入；网页可能把它们格式化为万股、万元或亿元，抓取器不得再次按页面展示倍率缩放。来源清单必须逐文件说明原始 API 单位与页面展示换算关系。
- 数值使用稳定的十进制文本，不使用千位分隔符或科学计数法；户数与股数等计数字段输出为整数。无法安全转换的可选数值写 `来源缺失`。
- 大宗交易核心字段为证券代码、交易日、成交价、成交量和成交额。缺少或非法时拒绝该行，并以 `block_trade` 阶段记录解析错误。
- 股东户数核心字段为证券代码、统计截止日、公告日和本次股东户数。缺少或非法时拒绝该行，并以 `shareholder_count` 阶段记录解析错误。
- 可选字段缺失时保留整行并写 `来源缺失`，包括收盘价、折溢价、买卖方、上次户数、变化值、变化率、户均值、市值和总股本。未知不能写成 `0`、空字符串或“无”。
- 折溢价机械计算公式为 `(成交价 - 收盘价) / 收盘价 × 100`，收盘价必须大于零。股东户数变化机械计算公式为 `本次户数 - 上次户数`；变化率公式为 `变化值 / 上次户数 × 100`，上次户数必须大于零。
- 来源派生值存在且与基础事实一致时保留来源值，basis 写 `source`；来源值缺失且基础字段足够时使用机械派生值，basis 写 `calculated`；无法计算时值和 basis 均写 `来源缺失`。
- 户数变化值按整数精确核对。折溢价率和户数变化率允许最多 `0.02` 个百分点的舍入差异。超过容差时保留基础事实，把冲突的派生值及 basis 写 `来源缺失`，并向对应数据集失败阶段追加解析错误。
- 非空响应中所有行都被核心字段校验拒绝时属于请求/解析失败，不属于无数据。
- 大宗交易的稳定身份由证券代码、交易日、成交价、成交量、成交额、买方名称和卖方名称组成。完全相同的多条源记录不得合并；加入从 1 开始的确定性重复序号后生成不同的本地标识。
- 股东户数快照的稳定身份由证券代码、统计截止日和公告日组成。
- 本地标识使用规范化身份文本的 SHA-256 摘要生成，分别带 `bt_` 与 `sh_` 前缀并保留 24 个小写十六进制字符。标识只代表本地稳定身份，不宣称是来源官方 ID。
- 大宗交易按交易日降序、证券代码升序、稳定标识升序排列；股东户数按统计截止日降序、公告日降序、证券代码升序、稳定标识升序排列。排序后按每证券上限截断。
- 请求成功但没有可用记录时，大宗交易使用 `block_trade_no_data`，股东户数使用 `shareholder_count_no_data`。请求、响应结构或解析失败分别使用 `block_trade` 和 `shareholder_count`。
- 单个证券失败只影响对应证券和数据集。成功结果、另一数据集结果和其他阶段错误必须保留。
- 独立抓取器的成功判定以请求结果为准：一个数据集全部失败、另一个数据集至少有一次正常响应，包括正常空响应，命令返回零；两个数据集对全部有效证券均请求或解析失败时，先写完产物再返回非零；全部正常无数据时返回零。
- 每次运行确定性覆盖本阶段管理的两个 CSV、两个来源清单条目和 `market_activity_`、`block_trade`、`shareholder_count` 相关错误记录；其他来源条目、其他阶段错误和其他文件保持不变。
- 来源清单继续使用现有 schema，不新增顶层或条目字段。两个 CSV 各有一条 `public_market_data`、东方财富、`待验证` 条目。
- 每条来源清单的 `period_or_basis` 写明报表名、研究截止日、回溯窗口、单证券上限、过滤顺序、排序方式、API 原始单位和页面展示换算；`missing_behavior` 写明无数据/失败阶段、当前查询可能受来源后续修订影响，以及不得推断吸筹、筹码集中、资金意图或价格方向。
- 一键准备流程增加 `--market-activity-source`、`--market-activity-fixture-scenario`、两组 lookback/limit 参数和 `--skip-market-activity`。所有窗口和上限必须为正数。
- 一键准备默认运行市场行为事实阶段。普通来源默认解析为 `eastmoney`，fixture 股票池默认解析为 `fixture`，显式来源参数优先。
- `--skip-market-activity` 跳过两个数据集，不提供分别跳过大宗交易或股东户数的开关。未跳过时总是调用独立抓取器。
- 两个 CSV 加入一键准备的受管输出清单；自动准备清单记录解析后的来源、fixture 场景、两组窗口、两组上限和跳过状态。
- 一键准备把市场行为事实视为可选阶段。独立抓取器非零时向标准错误输出带脚本名称和退出码的告警，但不改变核心研究包的成功退出码。
- 第一版不实现缓存、增量更新或断点续跑。相同输入和 fixture 必须产生完全稳定的 CSV 行、记录标识、来源条目和本阶段错误记录。
- 更新 A 股数据来源契约，把两个 CSV 加入研究数据包可选文件清单并说明字段、来源等级、研究截止日和缺失行为。
- 更新 AkShare/公开来源目录：东方财富 `RPT_HOLDERNUM_DET` 用于当前个股历史快照；巨潮股东户数接口用于后续季度官方交叉验证，不再用“巨潮优先”暗示其能替代当前历史抓取；记录大宗交易首个 5000 行不翻页的限制。
- 领域 Skill 只在垂直插件规范源修改，再运行现有同步流程传播到命名 Agent bundle。不得直接只改 bundle 副本。
- 本规格不需要 ADR。来源选择、文件形状和可调窗口都可以在后续独立 issue 中局部替换，没有形成难以逆转的架构承诺。

## Testing Decisions

- 整个功能只使用一个外部测试接缝：通过子进程调用公开 CLI，观察退出码、标准错误告警和研究数据包文件。测试不得导入或断言私有 HTTP helper、分页循环、重试计数或内部函数调用。
- 主要验收入口是一键研究数据包准备 CLI，用于验证默认运行、实际来源解析、参数透传、整阶段跳过、失败降级、受管输出、自动准备清单以及核心研究包不被阻断。
- 只有一键准备会吞掉的独立退出语义通过市场行为事实 CLI 直接验收，包括致命输入错误、全部正常无数据、一个数据集全失败但另一个有正常响应、两个数据集全失败。
- 所有验收均使用 `--source fixture` 或 fixture 股票池，不访问真实东方财富网络。Fixture 必须模拟分页响应、未来公告、坏行、派生值冲突和完全重复交易，而不是绕过公开抓取流程直接写最终 CSV。
- 成功场景验证两张表的固定表头、基础计量单位、来源等级、默认窗口、每证券上限、稳定排序、稳定记录标识和来源清单口径。
- 单位场景使用满足 `成交额 = 成交价 × 成交量` 的源数据验证成交量和成交额没有被多乘或少乘 10000；股东户数、市值、户均持股和总股本同样验证 API 基础单位不会按页面展示单位重复缩放。
- 研究截止日场景使用多页数据验证：大宗交易日不能晚于 `as-of`；股东户数的统计截止日和公告日都不能晚于 `as-of`；首页被未来可见记录占据时仍会继续分页找到历史可见快照。
- 截断场景验证先执行研究截止日、回溯窗口和核心字段校验，再按稳定排序截取每证券上限，不能用原始返回条数提前截断。
- 派生值场景验证来源值一致、来源值缺失可计算、输入不足无法计算、整数变化冲突和比率超过 `0.02` 个百分点容差五类结果及 basis 标记。
- 坏行场景验证缺少核心字段的行被拒绝并记录对应失败阶段，可选字段缺失的行被保留且写 `来源缺失`，非空响应全部被拒绝时不能写无数据状态。
- 重复交易场景验证完全相同的两笔大宗交易都被保留、标识不同且稳定；相同命令重复运行后文件内容不漂移。
- 无数据场景验证两个数据集分别使用 `block_trade_no_data` 和 `shareholder_count_no_data`，独立命令返回零，CSV 保持带表头空文件。
- 部分失败场景验证失败证券不清空成功证券，一个数据集失败不清空另一个数据集，统一错误文件保留其他阶段既有错误。
- 全失败场景验证独立命令在写完两个空 CSV、两个来源条目和错误记录后返回非零；一键准备对相同场景只告警并继续生成核心研究包。
- 输入场景验证文件缺失、缺少 `code` 列、全部代码非法和部分代码非法。前三者非零且有稳定产物，部分非法保留有效代码结果并记录 `market_activity_input`。
- 跳过场景验证一键准备不调用市场行为事实阶段、不生成本阶段数据内容，并在自动准备清单中明确记录跳过状态。
- Manifest 场景验证按文件名替换本阶段旧条目、不生成重复条目、保留其他阶段条目，并包含报表、研究截止日、窗口、上限、排序、单位、修订风险和禁止推断边界。
- 重跑场景验证本阶段旧错误被替换而不是累积，其他阶段错误保持不变；两个 CSV 与来源条目确定性覆盖，不需要缓存或增量状态。
- 文档场景验证两个可选文件和关键字段已进入 A 股研究数据包契约，来源目录使用 `RPT_HOLDERNUM_DET` 并记录大宗交易分页风险，规范源和命名 Agent bundle 完全同步。
- 测试先例沿用现有研报抓取器专项检查和一键准备检查的子进程、临时目录、fixture 与外部产物断言模式，不引入新测试框架。
- 完成实现后必须运行新增市场行为事实专项检查、现有一键准备检查、A 股数据契约检查以及 `python3 scripts/check.py`。不得跳过、禁用或改弱既有检查。

## Out of Scope

- 把大宗交易或股东户数变化自动解释为机构吸筹、主力买卖、筹码集中、利益输送、资金意图或价格方向。
- 计算市场行为评分、聚合信号、买卖方向、异常阈值、排名或预警。
- 输出大宗交易后的 1、5、10、20 日涨跌幅或其他未来表现标签。
- 输出股东户数区间对应的股价涨跌幅，或建立户数变化与股价表现之间的因果关系。
- 修改风险摘要、handoff、研究 note、dashboard、comps、估值排序、业务暴露或 idea shortlist。
- 接入龙虎榜、互动易、财务三表或其他 `a-stock-data` 端点。
- 使用巨潮作为第一版自动回退来源，或实现东方财富与巨潮的自动交叉验证。
- 全市场扫描、主题到证券代码推断、用户额外代码列表或非 A 股证券支持。
- 缓存、增量更新、断点续跑、数据库存储、调度服务或并发抓取。
- 把当前查询结果声明为完整双时态历史数据库；东方财富后续修订可能改变同一研究截止日的现时查询结果。
- 新增 AkShare、pandas、requests 或其他运行时依赖。现有 AkShare 代码只作为端点和字段目录参考。
- 直接复用外部项目的运行时 Skill 或把外部项目作为子模块、包依赖或隐式执行入口。
